# Documentation Standard

---

# Purpose

This standard defines how documentation is created and maintained within IA Engineering.

Documentation is considered a first-class engineering artifact and must evolve alongside the project.

---

# Scope

This standard applies to:

- All Employees
- All Workflows
- All Projects using IA Engineering

---

# Official References

The following references are considered authoritative:

- Markdown Guide
- Docs as Code Principles
- Diátaxis Documentation Framework (when applicable)

Projects may adopt additional documentation frameworks when required.

---

# Industry Best Practices

Documentation should:

- remain accurate;
- be versioned with the code;
- be easy to navigate;
- avoid duplication;
- be updated whenever the software changes.

---

# IA Engineering Additions

## Documentation as Deliverable

Documentation is part of the Definition of Done.

A feature is not considered complete if the required documentation is missing.

---

## Living Documentation

Documentation must evolve together with the project.

Outdated documentation should be corrected or removed.

---

## Single Source of Truth

Each piece of information should exist in one authoritative location.

Duplicate documentation should be avoided.

---

## Project Documentation

Every project should include, when applicable:

- README
- Installation Guide
- Architecture Documentation
- API Documentation
- User Documentation
- Development Documentation
- Changelog

---

# Responsibilities

Every Employee must:

- update documentation related to their changes;
- avoid creating obsolete documentation;
- keep documentation clear and concise;
- follow the project documentation structure.

---

# Forbidden Practices

Do not:

- leave outdated documentation;
- duplicate the same information;
- document unfinished features as completed;
- ignore documentation updates during development.

---

# Rationale

Following this standard provides:

- easier onboarding;
- improved maintainability;
- better collaboration;
- consistent project knowledge;
- reduced technical debt.
