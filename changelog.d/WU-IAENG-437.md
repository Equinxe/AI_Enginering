### Fixed

- `install-hooks.sh` merges into an existing `.claude/settings.json` that has no `hooks` key, the commonest shape of a project's own settings. That covers a file with only `permissions`, only a `$schema`, or nothing (`{}`), and a file with `"hooks": null`. Such a file was refused with "exists and differs, and the merge failed. Not changed." and exit 1, and `--check` reported "the merge computation failed". The cause, never printed, was `jq: null (null) has no keys`: the near-miss scan read the missing key. Now the framework's hook entries and its statusLine are added, and every other key is kept as it was: `permissions`, `env`, `model`, `$schema`. A project's own `statusLine` is wrapped, as in any other `settings.json`. `--check` names as absent the same entries that a run then adds (DEF-465-01, WU-IAENG-437)
- `install-hooks.sh` says why it cannot merge a `settings.json`, and the run's refusal and `--check`'s fault record give the same reason. A comment (`//` or `/* */`), which JSON does not allow, is named by its line, with the remedy: remove it and re-run, and put a note in a `"$comment"` key instead. Any other JSON error is named by `jq`'s own message. A `hooks` that is not an object, absent or null, such as `"hooks": false`, is refused with that reason; before, it reached the merge, which failed (WU-IAENG-437)

### Notes

- On v0.0.14 and v0.0.15, `install-hooks.sh` refuses a `.claude/settings.json` that has no `hooks` key: it prints "exists and differs, and the merge failed. Not changed." and exits 1, and the hidden cause is `jq: null (null) has no keys`. Until you upgrade, add `"hooks": {}` to the file first, then re-run `install-hooks.sh`: it adds the framework's entries and keeps the rest. After the upgrade, re-run it on the file as it is (WU-IAENG-437)
