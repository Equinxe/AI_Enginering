### Fixed

- `validate-framework.sh`, `install-hooks.sh`, `usage-dashboard.sh` and `check-review-recorded.sh` remove only the carriage return that ends a line (`Standards/CODE_QUALITY_STANDARD.md`, The Check Convention, Shell Scripts, rule 3). They removed every one, so a value with a CR inside read the same as the value without it and a check passed on the difference it exists to see: a chain step, a Work Unit id or owner, a workflow path or step count, a stack, a README or CLAUDE.md version line, a roster name, a review login, a price. A CRLF checkout reads as before. On Git for Windows, grep itself still removes every CR of a CRLF file before a script sees it (#433) (#326, WU-IAENG-397)
- `validate-framework.sh` reads VERSION.md's codename and Next Milestone with only their bold markers removed: the match ends at the closing `**`, so the CR that ends a CRLF line is never in it, and one before the `**` is inside the line and is kept (#326, WU-IAENG-397)
- `install-hooks.sh`, merging into an existing `.claude/settings.json`, prints a TAB, line feed or carriage return inside a project's near-miss command as a space, as `--check` does, where it removed the CR and printed the rest raw. A CR there could draw the command over its own warning line. Other control bytes still reach the terminal on that path (#434) (#326, WU-IAENG-397)
