### Added

- An existing repository, whose `main` is already on its remote, has an adoption route that works (Director decision, 4 November 2026). It creates `develop` from `main`, adopts on `chore/adopt-ia-engineering`, and merges that branch into `develop` through a Pull Request, where `Work Unit Exists` and `Employee Trailer` read both adoption commits. `main` receives the adoption at the project's first release. `README.md` Getting Started gives the commands, and `Workflows/ONBOARDING.md` (0.0.18) gains the section The adoption route. Both say what happens until that release: `main` and whatever deploys from it stay as they were, `ghcr-publish.yml` does not run, and a hotfix from `main` cannot claim a Work Unit without adopting `main` in part. They also say that an adopting project's first release is not rehearsed yet (#469), and that the adoption Pull Request is over the 1,500-line review limit, so `PR Size` passes only once the Director applies `size/approved` (WU-IAENG-436)
- `README.md` says what the bootstrap writes that an existing project may not want, the starter `Dockerfile` and `ghcr-publish.yml`, and how to decline each before the adoption commit. A deleted file is reported by the drift check at every session start until #464 is fixed; `ghcr-publish.yml` can instead be kept and made manual, which the drift check accepts (WU-IAENG-436)
- `README.md`, `Workflows/ONBOARDING.md` Step 1 item 4 and `Workflows/PROJECT_BOOTSTRAP.md` (0.0.17) Step 4 say to run `git config core.hooksPath` before `install.sh`. A path means the project already runs hooks of its own, which the install stops silently until #280 is fixed (WU-IAENG-436)
- `Workflows/ONBOARDING.md` Step 5 and `README.md` say that on a private repository on GitHub Free, where GitHub offers no branch protection, only the local git hooks and the CI checks enforce the rules, and a red check does not block a merge (WU-IAENG-436)
- `README.md` and `Workflows/PROJECT_BOOTSTRAP.md` Step 4 item 5 say that the adoption commit carries a `RISK:` record, since it adds CI workflows that the starter Risk Map classes as sensitive (WU-IAENG-436)
