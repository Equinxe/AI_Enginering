### Added

- `Adapters/ai-runtimes/claude-code/DAILY_USE.md` (0.0.1), linked from `README.md`: the daily loop of an adopting project with Claude Code, from starting a Work Unit to coming back to `develop`. It says where the Director approves a plan (in the session; `Decision: approved` is the Code Reviewer's line on the Pull Request), that an Employee's worktree starts from `main` so the Employee branches from `origin/develop`, who runs `gh pr merge` and with which flags, and how the worktree and the branch are cleaned up, with git's refusals and what to do about each (WU-IAENG-449)
- The same page says where a human runs a command a guard refused: in a terminal outside Claude Code, where the guards do not run because `PreToolUse` runs only on Claude's tool calls. The `!` prefix is labelled derived, not verified. An Employee stops and reports a refusal, a false positive included, instead of rewording the command past it (WU-IAENG-449)
- `Adapters/ai-runtimes/claude-code/TROUBLESHOOTING.md` (0.0.18) starts with an index from a message to its entry. Entry D maps every reason the guards print after `iaeng: BLOCKED —`, the Stop gate's lines and the post-edit lint's lines to what to do. Entry E covers Claude Code's own refusals: the worktree isolation check, a permission prompt and an auto-mode block (WU-IAENG-449)
- `Governance/TROUBLESHOOTING.md` (0.0.13) entry AD: on Windows, `Filename too long` in a worktree nested under `.claude/worktrees/` is fixed by `git config --global core.longpaths true`, set by the Director, never by an agent (#402, WU-IAENG-449)
