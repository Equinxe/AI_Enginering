### Added

- `Adapters/ai-runtimes/claude-code/DAILY_USE.md` (0.0.1), linked from `README.md`: the daily loop of an adopting project with Claude Code, from starting a Work Unit to coming back to `develop`. It says where the Director approves a plan (in the session; `Decision: approved` is the Code Reviewer's line on the Pull Request), that an Employee's worktree starts from `main` so the Employee branches from `origin/develop`, who runs `gh pr merge` and with which flags, and how the worktree and the branch are cleaned up, with git's refusals and what to do about each. The cleanup first checks that `origin/develop` has every commit of the branch and of its copy on `origin`, because `git branch -d` compares a pushed branch with its own remote copy, not with `develop`. It lists the ignored files that `git worktree remove` deletes without refusing, and a dispatched merge or cleanup runs in the main checkout, without worktree isolation (WU-IAENG-449)
- The same page says where a human runs a command a guard refused: in a terminal outside Claude Code, where the guards do not run because `PreToolUse` runs only on Claude's tool calls. The `!` prefix is labelled derived, not verified. An Employee stops and reports a refusal, a false positive included, instead of rewording the command past it (WU-IAENG-449)
- `Adapters/ai-runtimes/claude-code/TROUBLESHOOTING.md` (0.0.18) starts with an index from a message to its entry. Entry D maps every reason the guards print after `iaeng: BLOCKED —`, the Stop gate's lines and the post-edit lint's lines to what to do. Entry E covers Claude Code's own refusals: the worktree isolation check, a permission prompt and an auto-mode block (WU-IAENG-449)
- `Governance/TROUBLESHOOTING.md` (0.0.14) entry AE: on Windows, `Filename too long` in a worktree nested under `.claude/worktrees/` is fixed by `git config --global core.longpaths true`, set by the Director, never by an agent. A setting in the project's own configuration does not reach the framework submodule (#402, WU-IAENG-449)

### Changed

- `Workflows/FEATURE_DEVELOPMENT.md` (0.0.17), Step 8: before anything is removed or deleted, `develop` is confirmed to have every commit of the feature branch and of its remote copy, since `git branch -d` checks the branch's upstream, not `develop`. A worktree that has the feature branch checked out is removed before the branch is deleted, never with `--force`, after its ignored files are listed, and a refusal is reported to the Director. The Main Agent's standing exception does not name that removal, so after a merge it executed it dispatches the removal to an Employee working in the main checkout, or the Director runs it, until the Director decides otherwise (#490, WU-IAENG-449)
