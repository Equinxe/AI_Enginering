### Fixed

- The context status line now also deletes the orphan `.*.tmp` files in its state directory once they are older than 24 hours (issue #345). A render killed between its write and its rename, as a status line run under a timeout can be, left its temporary file behind, and the hourly cleanup deleted only `*.pct` and `*.alert`, so these files piled up. The context alert's own temporary files go the same way. The guards are the ones the cleanup already had: regular files the user owns, at the top of the directory, never through a link, and at most once an hour.
- The context hook tests no longer write into the user's real `iaeng-ctx-<uid>` directory (issue #345). A case whose `TMPDIR` the rule refused fell back to `/tmp`, and on Windows that is the user's own `TEMP`, where `sess-bad-tmp.pct` was left. `hooks/context-dir.sh` now reads `IAENG_CTX_TEST_FALLBACK`, for the tests only, in place of `/tmp`. The same rule judges it, and every case sets it to a scratch directory. Both tests end by checking that the real directory gained or changed no file. With no override set, the directory each hook names is the same as before for every `TMPDIR` form.
- Two Code Reviewer minors of #343: `hooks/context-dir.sh` writes its backslash as `$'\x5c'`, which holds no pair of backslashes for a copy to halve, and its comment now claims only that. The shared writer-and-reader test counts the `.pct` files it finds with `wc -l`, so a path with a space no longer counts as two files.
