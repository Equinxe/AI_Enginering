### Fixed

- `block-escape-hatches.sh` allows a keyword read of `core.hooksPath` in another command's arguments: `echo "$(git config --get core.hooksPath)"`, ``echo `git config --get core.hooksPath` `` and `printf '%s\n' "$(git config --get core.hooksPath)"` pass, up to 16 reads in one command segment. A write in the same command stays refused: in a substitution, beside the read, joined across a substitution, in another substitution, or as a `-c` option. A legacy read in a substitution, ``echo `git config core.hooksPath` ``, stays refused, and its refusal now names the `--get` read to run. The hooks README's remedy for the refused legacy reads, to use `--get`, now holds for these forms (#272, WU-IAENG-455)
- `git commit-tree -p <parent>` is no longer refused as an interactive command. The interactive rule reads `rebase`, `add`, `commit`, `checkout` and `reset` only as whole command names, so `commit-tree`, `commit-graph` and `checkout-index` are other commands. `git commit -p` and `git-commit.exe -p` stay refused (#261, WU-IAENG-455)
- An `rm` of a path under `.git` with no `-r`, such as the stale `.git/index.lock` a session leaves behind, is still refused, but its reason no longer calls it a recursive removal. It names the path, and the remedy: wait until the session that holds the lock has finished, or ask a human to remove the lock by hand. Whether to allow such an `rm` is a Director decision not yet taken (part of #235, WU-IAENG-455)
- A quoted message's last word after a `/` no longer reaches the rules. `strip-quotes.awk` keeps a dropped quoted region's last path component only when it names git, a dashed `git-<subcommand>`, `gh`, `rm` or `printf`, or when the region is glued to the text after it. So `git commit -m "docs: see Standards/core.hooksPath"` and `git commit -m "see docs/x--no-verify"` are allowed, and a quoted command path such as `"/c/Program Files/Git/cmd/git.exe"` is read as before (code review of PR #485, F3, WU-IAENG-455)
