### Changed

- `install-hooks.sh` validates the shape of `.claude/settings.json` more strictly. The file must be strict JSON in the shape the Claude Code settings schema gives `hooks`: under each event a list of matcher groups, and each group an object whose `hooks` is a list. A byte order mark, a value JSON does not have (`NaN`, `Infinity`, a number such as `+1`, `01` or `.5`), and an event or group out of that shape are refused like a comment is: the file is left as it is, the run exits 1 and names the reason and its remedy, and `--check` reports the same reason as a fault. A carriage return is whitespace wherever it stands, so CRLF, CR-only line endings and a CR inside a line are read as before. A refusal that quotes the file writes a control character as an escape, such as `\r` (WU-IAENG-441)
- `install-hooks.sh` writes atomically on every path. A new file and `--force` are written to a temporary file beside `.claude/settings.json`, read back, then renamed over it, as a merge already was. Every temporary file, a merge's included, is made with `mktemp` and removed on any exit. A symbolic link at that path, or anything there that is not a regular file such as a directory, is refused on every path, `--force` included, and `--check` reports either as a fault instead of an absent file (WU-IAENG-441)

### Notes

- After the upgrade, `install-hooks.sh`, and its `--check` that `check-framework-drift.sh` runs, may refuse a `.claude/settings.json` that an earlier version accepted. The message names what to correct: a byte order mark, a value such as `NaN`, or an event or group under `hooks` that is not a list. Correct it and re-run (WU-IAENG-441)
