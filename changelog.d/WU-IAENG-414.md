### Security

- In an adopting project, the git hooks now run in every linked git worktree. That includes the worktree Claude Code isolates an Employee in. A worktree has the framework submodule empty, and the relative `core.hooksPath` `install.sh` wrote named a directory that did not exist there. git ran neither `commit-msg` nor the data-policy `pre-commit`, and printed nothing: a commit signed `Employee: Claude`, or one staging an `.xlsx`, was accepted. `install.sh` now sets an adopter's `core.hooksPath` to the main checkout's framework hooks, as an absolute path, including when it is run from a worktree. The framework repository keeps `./Adapters/git-hooks`. `commit-msg` also finds the roster in the framework it belongs to. `install.sh --check` and `check-framework-drift.sh` (`--quick` too, so at session start) report the old relative value. A worktree subagent's Claude Code hooks were checked: they run with `$CLAUDE_PROJECT_DIR` set to the main checkout, so they were not affected (`Governance/TROUBLESHOOTING.md` entry AB; #368, WU-IAENG-414)

### Notes

- Adopting projects installed before this release: re-run `./ia-engineering/Adapters/scripts/install.sh` in the main checkout to replace the relative `core.hooksPath`. The session-start drift line names it until you do. Commits already made in a worktree were never checked by the hooks: before pushing them, run `check-employee-trailers.sh develop HEAD` and `data-policy-scan.sh --history develop..HEAD` on the branch. If the checkout is moved, re-run `install.sh`: the absolute value then names a directory that no longer exists (WU-IAENG-414)
