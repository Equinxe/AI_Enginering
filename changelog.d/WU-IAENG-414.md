### Security

- In an adopting project, the git hooks now run in every linked git worktree. That includes the worktree Claude Code isolates an Employee in. A worktree has the framework submodule empty, and the relative `core.hooksPath` `install.sh` wrote named a directory that did not exist there. git ran neither `commit-msg` nor the data-policy `pre-commit`, and printed nothing: a commit signed `Employee: Claude`, or one staging an `.xlsx`, was accepted.
  `install.sh` now sets an adopter's `core.hooksPath` to the main working tree's framework hooks, as an absolute path, including when it is run from a worktree. It finds the main working tree for a standalone clone, for a project that is itself a submodule of a superproject, and for a bare repository with worktrees (there, the worktree it runs from). The framework repository keeps `./Adapters/git-hooks`.
  `commit-msg` reads the roster of the framework it belongs to before the worktree's own `ia-engineering/` path, so a roster planted in a worktree's empty submodule directory is not read.
  `install.sh --check` and `check-framework-drift.sh` (`--quick` too, so at session start) report the old relative value. A worktree subagent's Claude Code hooks were checked: they run with `$CLAUDE_PROJECT_DIR` set to the main checkout, so they were not affected (`Governance/TROUBLESHOOTING.md` entry AB; #368, WU-IAENG-414)
- `commit-msg`, `pre-commit`, `pre-push` and `data-policy-scan.sh` ignore SIGPIPE. Under Git for Windows, `git commit … 2>&1 | head -n 0` (or `| head -1`) wrote a hook's refusal to a closed pipe. The hook died of SIGPIPE, git read exit 0, and the commit was created, whether it was signed `Employee: Claude` or staged an `.xlsx`. The failed write now leaves the hook's own exit 1 in force (#397, SEC-IAENG-414-05, WU-IAENG-414)

### Notes

- Adopting projects installed before this release: re-run `./ia-engineering/Adapters/scripts/install.sh` in the main checkout to replace the relative `core.hooksPath`. The session-start drift line names it until you do. Commits already made in a worktree were never checked by the hooks. Before pushing them, run from the main checkout, naming the worktree's branch: `./ia-engineering/Adapters/scripts/check-employee-trailers.sh develop <branch>` and `./ia-engineering/Adapters/scripts/data-policy-scan.sh --history develop..<branch>`. They cannot run inside the worktree, where `ia-engineering/` is empty. If the checkout is moved, re-run `install.sh`: the absolute value then names a directory that no longer exists (WU-IAENG-414)
