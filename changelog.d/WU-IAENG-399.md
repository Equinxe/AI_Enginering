### Security

- The drift cache directory can no longer resolve inside the project through a backslash (issue #342). `iaeng_cache_dir` in the hooks' `lib.sh`, which picks the cache directory at session start, and `cache_dir_canon` in `check-framework-drift.sh` split the path on `/` alone, but Windows reads a backslash as a separator. A part still to be made below an existing directory outside the project, such as `..\proj\cache`, or `proj\cache` with no `..` at all, was therefore kept as one name and never tested. Windows then created it inside the project, and the drift check kept its cache there. Both now read every backslash as a separator before the `.` and `..` test and in the walk. `--cache-dir` with a `\..` component is a usage error (64), as one with `/..` already was. One table of `/`, `\`, mixed and drive-letter spellings drives both copies of the rule, with each answer written by hand. The script and the hook are also run with a `\` spelling of the project, and they write nothing in it. The value comes only from `XDG_CACHE_HOME`, `HOME`, `TMPDIR` or `--cache-dir`, the user's own environment, so the tier is Low (sec-343) (#342, WU-IAENG-399)
- A cache directory spelt with a run of leading separators, such as `////localhost/C$/<path to the project>/x`, can no longer resolve inside the project on Windows. The walk went up to the root, and joining the root to the rest gave `//localhost/C$/...`, a network path to the project that nothing tested. Both copies now refuse a directory whose existing part resolves to the root, as they already refused `/<missing>/x`. The `/` spelling was accepted before this change. The `\` spelling, `/\\\localhost\C$\...`, was refused before, and reading the backslash as a separator would have opened it (SEC-IAENG-399-01, sec-360) (#342, WU-IAENG-399)

### Fixed

- The session-start hook no longer hangs when the cache home is spelt the Windows way and does not exist yet, such as `XDG_CACHE_HOME=C:\Users\me\.cache`. The hook passes `C:\Users\me\.cache/ia-engineering`, and the walk gave `C:\Users\me\.cache/` back to itself, so it never returned (measured: no answer within 20 s). That cache home is now used. A drive that does not exist, such as `Q:\cache/ia-engineering`, looped the same way at its root `Q:/`, in both copies. It is now refused, and the hook falls back to `$TMPDIR` (cr-360) (#342, WU-IAENG-399)

### Changed

- A direct `--cache-dir` spelt the Windows way with no `/`, such as `C:\Users\me\.cache`, that does not exist yet is now used. It was refused, and the check ran without a cache. On Linux a backslash in the cache directory is now read as a separator too, so a directory whose name holds one is read as two (#342, WU-IAENG-399)
