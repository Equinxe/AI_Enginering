### Fixed

- `generate-agents.sh` never replaces a project's own agent. An existing Claude Code project often keeps agents of its own in `.claude/agents/`, under names the Employees take (`code-reviewer.md`, `backend-engineer.md`), and the generator replaced such a file after a content diff only. An agent's path is now written only when it holds nothing, or a file with the generated header, the HTML comment opened on the first line after the frontmatter that is not blank. Anything else is left as it is: a file without that header, an empty file among them, a file that cannot be read, or an entry that is not a regular file, a dangling link among them. The generation names each such path with its reason, writes the other agents, exits 1 and prints the command that regenerates. `--dry-run` answers the same, and `--check`, with or without `--quick`, reports the path as `stale`, `not a generated agent`. `Adapters/ai-runtimes/README.md` also states that the `.claude/agents/` ignore rule hides every agent the project adds there later; the change to that rule is tracked in #525 (#516, WU-IAENG-454)
- Agents keep the sentence naming the `ia-engineering/` prefix when the framework directory is a symbolic link or a junction. The framework's directory in the project is found by walking up the path the generator was run by as well as the framework's physical path, and the command `--check` prints goes through the link, from whichever directory the check was run. The root the agents name stays the framework's physical path (#476, WU-IAENG-454)
