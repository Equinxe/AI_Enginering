### Added

- Session start checks that each roster Employee has an agent in `.claude/agents/`, and that each agent's framework root is the project's framework: the same directory, written as the generator writes it, so a root that reaches the framework through a symbolic link or a junction is stale. When an agent is missing (a fresh clone, a second machine) or stale (a moved project, agents from another clone or from before agents named a root), it prints one line naming them and the command that regenerates them. A second line says that until a named Employee can be dispatched, none is dispatched and never a generic agent in its place, and that a failed command goes to the Director. When `.claude/agents/` did not exist at session start, the second line also says to restart the session after the command, since Claude Code loads only the agents directories that existed when it started. When every agent is present and names this framework, it prints nothing. The check is `generate-agents.sh --check --quick`, in the same generator call that prints the tier map, and generates nothing. A root that is a network path is never opened (WU-IAENG-434)
- `check-framework-drift.sh`, without `--quick`, reports the agents as a fifth family, `agent`: one record per roster Employee, current, missing, or stale with its cause, and the command that regenerates them. Missing and stale agents count as drift to act on, and `--strict` exits 1 for them. `--quick` records the family as not evaluated, since comparing an agent costs a generation (#411, WU-IAENG-434)
- `generate-agents.sh --check --format tsv` gives a caller one record per agent, a summary line and the command to regenerate. `--check` says `missing:` for an agent that does not exist, apart from one that differs (WU-IAENG-434)
- In an adopting project, the pre-commit hook and the data-policy check refuse a `.md` file under a `.claude/agents/` directory, at any depth and in any letter case: the agents are generated in each clone and name that clone's framework root. They also refuse an entry committed where `.claude/` or `.claude/agents/` should be, such as a symbolic link to a directory that holds agents. A hand-written agent of the project's own takes an anchored rule in `.ia-engineering/data-policy.allow`. The framework repository's own agents, which name no root, are out of scope (WU-IAENG-434)
- `Templates/PROJECT_CLAUDE.md` (0.0.16) lists the fresh-clone procedure as three commands, the last of which generates the agents, to run before starting Claude Code in the clone. It says to run the generator again after every framework upgrade, and after the project moves `install.sh` too, since `core.hooksPath` still names the old path (#470, WU-IAENG-434)

### Fixed

- `generate-agents.sh` read a relative `--project` or `--roster` from the framework checkout. `--project .` run from an adopter's root wrote every agent into the framework's own gitignored `.claude/agents/` and exited 0, and session start, run with `CLAUDE_PROJECT_DIR` unset, showed the framework's tier map as the project's. Both are now read from the directory the script was run from (#418, WU-IAENG-434)
- The command `generate-agents.sh --check` prints to regenerate was a fixed `./Adapters/ai-runtimes/generate-agents.sh`, which exits 127 from an adopter's root. It now names the generator by the path that reaches it from the directory the check was run from, adds `--project` when the project is not that directory, and repeats every option that decided what was compared (`--map`, `--effort-map`, `--roster`, `--out`), quoting a path with a space or a non-ASCII letter (#412, WU-IAENG-434)
- `generate-agents.sh --check` counted an agent that differs in its mapping and names another framework root in the "mapping only" line as well as in the framework-root line, so the summary's counts added up to more than the agents that differ. That agent is now counted once, under the framework root, and the summary says how many of those also differ in the mapping (DEF-IAENG-456-01, WU-IAENG-434)

### Notes

- After upgrading, re-run `./ia-engineering/Adapters/ai-runtimes/generate-agents.sh` from the main checkout, then `./ia-engineering/Adapters/scripts/check-framework-drift.sh`: it now lists every agent that is missing or out of date with `Employees/`, with the command that regenerates them. In every other clone and on every other machine, run the generator once, as the fresh-clone block of `Templates/PROJECT_CLAUDE.md` says (#411, WU-IAENG-434)
- If your project has committed files under `.claude/agents/`, the data-policy check now refuses every Pull Request until they are untracked: `git rm -r --cached .claude/agents`, keep the `.claude/agents/` rule in `.gitignore` (re-running `install.sh` adds it back), and regenerate in each clone. A hand-written agent of the project's own stays committed with an anchored rule in `.ia-engineering/data-policy.allow` (WU-IAENG-434)
