### Fixed

- The `commit-msg` hook now checks the claims a merge carries even when it cannot classify the merge. It used to print "cannot classify this merge locally; CI will." and exit 0 before any rule ran. So `git merge --allow-unrelated-histories` with `Work Unit: WU-DEMO-999` created the merge locally, though the Work Unit Exists check refuses that commit, and an `Employee:` line naming no Employee passed the same way. The hook still prints the warning and still leaves CI to decide whether the merge needed a trailer. It now also resolves a `Work Unit:` claim through `check-work-units.sh --message`, refuses two claims, and validates every `Employee:` line, as it does on a clean merge. A git older than 2.38 has no `merge-tree --write-tree`, so there the hook cannot classify any merge of two parents. An octopus merge is still classified as authored, without merge-tree. On such a git too, every merge of two parents now has its claims checked. Classified merges and ordinary commits are checked as before (#408, WU-IAENG-429)
