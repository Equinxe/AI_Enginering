### Security

- The commit-msg hook and `check-employee-trailers.sh` now refuse an Employee trailer that git reads under another spelling: the key in any case (`employee:`), spaces or a tab before the colon (`Employee :`), no space after it (`Employee:x`), or an indented line folded into its value. Both checks validated only lines spelt `Employee: ` at column 0, so such a line passed them while `git log --format='%(trailers:key=Employee)'`, the reader `usage-dashboard.sh` uses, returned a name nobody had checked. Which lines are trailers is now git's own decision (`git interpret-trailers --parse --no-divider` in the hook, `%(trailers:key=Employee,unfold)` in the script), and each Employee trailer git reads must be accounted for by its own line spelt exactly `Employee: <Name>`, the lines checked against the roster. A variant is refused even when the name it carries is on the roster. A message whose trailers git cannot read is refused by the hook, and reported as not evaluated (exit 2) by the script (#338, WU-IAENG-396)
