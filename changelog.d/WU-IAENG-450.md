### Security

- `block-escape-hatches.sh` hardens command recognition. It recognises `git.cmd`, `git.com` and `git.bat` as git, and a dashed `git-<subcommand>` such as `git-push` or `/mingw64/libexec/git-core/git-stash`, with or without `.exe`, as git running that subcommand. It recognises `rm` under any path (`/bin/rm`, `./rm`), as `rm.exe` and in any case spelling, after a subshell's `(`, and with a target that ends at a `;`, `&`, `|` or `)` (WU-IAENG-450)
- `strip-quotes.awk` reads a command a third time when that reading differs from the other two. A command substitution is read as empty, so a flag glued to one, such as `"--force$(true)"`, `--fo$(true)rce` or a backtick form, is read whole. A quoted or escaped `;`, `&` or `|` is part of its word, so a git option's value such as `-C "a;b"`, or a substitution in it, does not cut its command in two. A rule refuses on a match in any reading. A call starts the same processes as before (WU-IAENG-450)
- A quoted word that holds a space keeps its place after a git option that takes a value and after `stash`, so `git stash "-m a b" list` is not read as the `list` read. After `--config-env` it keeps its key, so `git --config-env "core.hooksPath=V X" commit` is read as a write of `core.hooksPath` (WU-IAENG-450)
- The approval-label rule refuses a label that is not a static literal: a `gh pr|issue edit|create` label flag whose value holds a variable or a command substitution, such as `--add-label "control-change/$(echo approved)"`, and a `gh api` write that sets labels from one, or from a file with `-F …=@file`, including a field whose key holds a variable or a substitution, such as `-f "$(echo labels)[]=$V"`. A literal `$` in a quoted label is refused too. Its refusal names the reason. A label key or endpoint split by a quote or a backslash, such as `-F "la"bels[]=@f`, is read as the shell joins it. A field whose literal key names no labels, with a substitution in its quoted value, such as `-f "body=$(cat c.md)"`, is allowed. A `gh api` write in a command that names a label, as written or as the lexer reads it, or that holds a `$` or a backtick, now starts the rule's second `awk`, as a quoted label list already did (WU-IAENG-450)
- `strip-quotes.awk` finds the word before a quote or a substitution from the end of the text and keeps it while only whitespace follows, and skips its second reading when only the third can differ, so its work stays linear in the length of a command of many quoted regions or substitutions separated by whitespace: a call on one substitution followed by 5,000 quoted words took 0.5 s of CPU, against 18.5 s before this Work Unit, and the lexer reads 120 KB of quoted regions that hold a space, after a substitution, in 0.6 s (WU-IAENG-450)
- The 2,000-segment cap counts the third reading too. A command read three times is read up to 666 segments and refused from 667 (WU-IAENG-450)

### Fixed

- The `core.hooksPath` read exemptions accept a quoted git option value that holds a space: `git -C "/c/Program Files/repo" config --get core.hooksPath` and `git --git-dir="/c/my repo/.git" config --get core.hooksPath` are allowed. A value that holds only whitespace, and the legacy read `git config core.hooksPath` beside a quote, stay refused (#477, WU-IAENG-450)
